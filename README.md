# Retail Demand Forecasting

> Прогнозирование ежедневного спроса для 500 временных рядов с единым backtesting для статистических, ML- и DL-моделей.

## О проекте

Проект посвящён **offline-прогнозированию розничного спроса** на горизонте 28 дней.

Датасет содержит:

- **913 000 наблюдений**;
- **500 временных рядов**: 10 магазинов × 50 товаров;
- ежедневные данные за период **2013-01-01 — 2017-12-31**;
- **1826 наблюдений на один ряд**;
- целевую переменную `sales`.

В проекте последовательно выполнены EDA, диагностика временных рядов, backtesting статистических моделей, построение глобальных ML/DL-моделей и демонстрация методов обнаружения аномалий.

Источник данных: Kaggle — *Store Item Demand Forecasting Challenge*.

## Ключевой результат

В единой схеме rolling-origin backtesting лучший результат показал **XGBoost**:

| Модель | Тип | sMAPE, % | MAE | RMSE |
|---|---|---:|---:|---:|
| **XGBoost** | ML | **12.975** | **6.168** | **8.101** |
| LightGBM | ML | 13.042 | 6.200 | 8.141 |
| RandomForest | ML | 13.083 | 6.194 | 8.112 |
| NHITS | DL | 13.909 | 6.631 | 8.709 |
| NBEATS | DL | 13.917 | 6.635 | 8.741 |
| AutoETS | Statistical | 16.978 | 8.329 | 10.888 |
| AutoTheta | Statistical | 17.032 | 8.362 | 10.931 |
| AutoARIMA | Statistical | 18.651 | 9.092 | 11.765 |
| TFT | DL | 20.084 | 10.303 | 13.431 |
| SeasonalNaive | Statistical | 21.067 | 10.499 | 13.982 |
| Naive | Statistical | 25.089 | 13.929 | 18.250 |

По сравнению с лучшей статистической моделью `AutoETS` XGBoost снизил sMAPE примерно на **4.00 процентного пункта**, или на **23.6% относительно**.

> Результаты относятся к конкретной схеме валидации и набору признаков данного проекта. Они не означают, что XGBoost в общем случае лучше статистических или нейросетевых методов.

## Схема валидации

Все модели сравниваются на одинаковых out-of-sample периодах:

| Параметр | Значение |
|---|---:|
| Forecast horizon | 28 дней |
| CV windows | 3 |
| Step size | 28 дней |
| Refit | `False` |
| Time series | 500 |
| Forecast points per model | 42 000 |

Используются три неперекрывающихся rolling-origin окна. Для каждой модели оцениваются прогнозы только после соответствующего `cutoff`.

Основная метрика — **sMAPE**. Дополнительно рассчитываются **MAE** и **RMSE**.

## Этапы проекта

### 1. EDA и диагностика временных рядов

В первом ноутбуке:

- проверяются пропуски, дубликаты и регулярность временной сетки;
- данные переводятся в формат `unique_id | ds | y | store | item`;
- исследуются общий тренд и календарная сезонность;
- анализируются ACF и PACF;
- выполняется STL-декомпозиция с недельным и годовым периодами;
- проводится ADF unit-root диагностика;
- проверяются первое и сезонное дифференцирование;
- анализируются различия масштаба между 500 рядами.

В данных выражена **недельная сезонность**, а уровни спроса заметно различаются между `store-item`. Нулевые продажи встречаются крайне редко, поэтому выраженной проблемы intermittent demand нет.

ADF интерпретируется осторожно: результат чувствителен к выбору детерминированной части (`c` против `ct`), поэтому один p-value не используется как универсальное доказательство стационарности.


### 2. Статистические модели

Сравниваются пять моделей из `StatsForecast`:

- `Naive`;
- `SeasonalNaive`;
- `AutoARIMA`;
- `AutoETS`;
- `AutoTheta`.

Лучшая статистическая модель в текущей CV-схеме — **AutoETS**:

- sMAPE: **16.978%**
- MAE: **8.329**
- RMSE: **10.888**

Для выбранного ряда дополнительно выполняется диагностика out-of-sample residuals и демонстрируются prediction intervals.


### 3. Machine Learning

Глобальные ML-модели:

- `LightGBM`;
- `XGBoost`;
- `RandomForest`.

Используются:

- лаги `1, 7, 14, 28`;
- rolling-признаки;
- `dayofweek`;
- `month`;
- `store` и `item` как статические признаки;
- локальное масштабирование target по каждому `unique_id`.

Такой подход позволяет одной модели использовать информацию сразу из всех 500 рядов, сохраняя различия между отдельными сериями.


### 4. Deep Learning

Сравниваются:

- `NBEATS`;
- `NHITS`;
- `TFT`.

Модели обучаются через `NeuralForecast`. Для устойчивости к различиям масштаба используется robust scaling.

В текущей конфигурации лучшие DL-результаты показывают `NHITS` и `NBEATS`, однако три tree-based ML-модели дают меньшую sMAPE.

### 5. Обнаружение аномалий

На примере `store_1_item_1` рассматриваются три разных диагностических подхода:

1. **Rolling Z-score** — порог рассчитывается только по прошлым значениям;
2. **ETS residual diagnostic** — анализ больших остатков статистической модели;
3. **Isolation Forest** — использует lag- и rolling-признаки без `np.roll` и wrap-around leakage.

Эти методы используют разные определения необычного наблюдения, поэтому их флаги не обязаны совпадать. Обнаруженная аномалия также не объясняет бизнес-причину события.

## Воспроизводимость и ограничения

- Временная валидация не перемешивает наблюдения случайным образом.
- Forecast horizon и CV-окна одинаковы для всех сравниваемых моделей.
- Итоговые метрики считаются по реальным out-of-sample прогнозам.
- Текущая конфигурация использует `refit=False`; при полном переобучении модели на каждом cutoff результаты могут измениться.
- Проект демонстрирует исследовательский forecasting workflow и не позиционируется как готовая production-система.
- Anomaly detection выполняется без размеченного ground truth и поэтому трактуется как диагностический анализ, а не как supervised quality benchmark.

## Основные выводы

- Недельная сезонность является важной частью структуры спроса.
- Масштаб продаж существенно различается между временными рядами, поэтому локальное масштабирование важно для глобальных моделей.
- `AutoETS` — лучший статистический benchmark в текущей схеме.
- `XGBoost`, `LightGBM` и `RandomForest` показывают наиболее низкую ошибку среди проверенных подходов.
- Лучший итоговый результат — **XGBoost, sMAPE = 12.975%**.
- Сложность модели сама по себе не гарантирует более высокое качество: в текущей конфигурации `TFT` уступает как tree-based ML, так и AutoETS.
